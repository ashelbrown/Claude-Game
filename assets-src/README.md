# Asset pipeline

Every model in STARFALL is generated by a Python script running in Blender. The
scripts are the source of truth; the `.fbx` files under
`StarfallUnity/Assets/Resources/Art/` are build products you can delete and regenerate.

## Regenerating

```bash
blender --background --python tools/blender/weapons.py     # 12 weapon archetypes
blender --background --python tools/blender/enemies.py     # enemy characters (rigged)
blender --background --python tools/blender/environment.py # modular level kit
```

Each script writes FBX into `StarfallUnity/Assets/Resources/Art/<category>/` and a preview
render into `assets-src/previews/`. Previews exist so the models can be reviewed
without opening Unity.

## Conventions

- Modelled in Blender axes (Z up, +Y forward) and exported with
  `axis_up='Y', axis_forward='-Z'`, so Unity receives Y-up / Z-forward assets at
  1 unit = 1 metre.
- Weapons point their muzzle along local **+Z** after import, with the origin at
  the grip — that is the point Unity parents to the hand/camera.
- Material slot order is fixed across every weapon so the game can recolour a
  known slot: `0 body · 1 dark · 2 grip · 3 glow`. Slot 3 is tinted per damage
  element and slot 0 per rarity at runtime.
- No textures. Everything is flat-shaded colour plus emission, which keeps the
  look consistent and the import step trivial.
